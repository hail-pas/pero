# 注册、组织邀请与应用授权

## 入口与职责

- 独立注册：`/sso/register`，使用平台注册策略。应用注册：OIDC `/oauth2/authorize` 加 `prompt=create`（不可与其他 prompt 组合），使用目标应用策略。
- 个人注册支持邮箱、手机号或允许注册的第三方身份源；配置可用通知渠道。第三方邮箱也必须在本站验证。组织专用应用不开放个人自助注册。
- 组织邀请：Owner/Admin 按现有成员治理权限发出邀请，邮件链接进入统一注册页；新用户通过邀请邮箱证明创建账户、个人空间及组织成员关系，既有用户通过有效账户会话（含已启用的 MFA）和一次性邮箱邀请确认加入；平台管理员仍需近期身份认证。不能绕过组织状态、成员上限、邀请角色、应用准入及 MFA。全局紧急停止阻止所有注册完成和邀请接受。

## 应用配置和回调

应用触发注册或组织邀请前，必须配置 OAuth Client 的 `login_uri` 为应用自己的 HTTPS 登录入口，不包含查询参数或 fragment，例如 `https://app.example.com/login`。它不同于 `redirect_uri`（OAuth 回调）。应用登录入口应支持可选的 `tenant_id`；收到 `enrollment_status=cancelled` 或 `enrollment_status=expired` 时分别显示取消或授权过期，等待用户选择下一步。正常入口生成新的 state、nonce、PKCE verifier/challenge，然后跳转 Pero 授权端点。

应用注册发起阶段必须持有已验证的 OAuth 请求；若首次提交联系方式前授权已失效，须从应用重新发起，不能降级成平台注册。同一浏览器内且短期授权请求仍有效时，注册事务成功后建立 SSO Session，按原请求恢复 OAuth Authorization；个人注册绑定新用户个人空间。超过授权请求有效期或跨设备时，不重放原请求，返回已登记 login URI 并由应用启动新授权。组织邀请绑定来源客户端及组织，接受成功后返回 login URI 并传递目标 tenant_id；无应用来源时进入账户门户。原生应用可通过受控 HTTPS App Link 实现登录入口。应用始终独立验证 token 和租户；入口参数不是凭证。取消时有效原请求返回 `access_denied` 与原 state，否则返回登录入口或账户门户。登录失败可重新认证，不重复创建账户。

## 生命周期及数据

注册申请有效期 24 小时，平台或应用邀请 72 小时，组织邀请 7 天；第三方注册证明短期有效。授权请求默认 600 秒，授权码默认 120 秒。注册事务创建用户、身份及应用资格或组织成员，并消费申请/邀请；事务提交后建立会话，不在注册服务签发 OAuth token。注册申请保存 client_id 与可空 auth_request_id，组织邀请保存 client_id 与 accepted_user_id；OAuth client 保存 login_uri。门户申请绑定发起账号。组织邀请关联当前投递任务。

## 安全与失败处理

邀请和验证令牌哈希入库，HttpOnly Cookie 承载待办理流程，原授权恢复要求浏览器 nonce 和匹配请求。已结束邀请仅可查看状态，不可再次创建身份。组织或应用的访问资格始终由现有授权流程校验。应用应处理 OAuth 错误以及用户未获得应用访问资格的情况。
